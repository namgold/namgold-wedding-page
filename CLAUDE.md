# wedding (linhhy.namgold.com)

Wedding page for namgold. Child repo of the `namgold.com` parent; see `../CLAUDE.md` for conventions.
Not to be confused with `~/devbox/wedding`, the private planning-notes repo.

## Status
Frontend and backend are built and live (see `SPEC.md`), but with PLACEHOLDER content. Read `progress.md` (handoff) and `DECISIONS.md` before starting any work. Doc roles: `SPEC.md` = what is built and the owner's requirements, `DECISIONS.md` = why, assumptions and open questions, `progress.md` = handoff and what is left. ## Stack
- `frontend/` — Next.js (static export, TypeScript, Tailwind v4). Multi-stage Dockerfile: Node builds `out/`, nginx:alpine serves it. No Node in production.
- Routes: `/invitation` (groom, Nha Trang), `/ceremony` (bride, Tan Hoi, Lam Dong), `/wedding` (Ho Chi Minh City), each in Vietnamese; English at `/en/<slug>`. **No central page**: `/en` and `/index.html` are 404 on purpose, and `/` serves the `/wedding` page (owner, 2026-11-21; nginx `try_files /wedding.html`, URL stays `/`), and no page may link to or mention another place (guests must not learn the other URLs exist). The 3 site QRs point at these URLs: never break one after it is printed (add an nginx redirect). Per-place data (date, venue, hall, ceremony and reception names, dress code, timeline, lunar) is in `places` in `src/content/places.ts` (fields listed in `SPEC.md` "Per-place config"; copy strings use `{ceremony}` and `{reception}` placeholders, filled at render, so copy stays serializable) (server-only: keep it out of client components so it stays out of the shared bundle); shared data in `wedding` in `data.ts`. Copy lives in `frontend/src/content/{vi,en}.ts`, data in `data.ts`. **Many values are still placeholders (hero short names, photos, wishes); the owner has replaced some (venues, halls, dates, bank accounts): check before assuming.** The lunar date is a hardcoded string.
- `api/` — Go (stdlib `net/http`, `modernc.org/sqlite`, no cgo), compose service `api` on the internal network only, SQLite in the `wedding-data` volume at `/data`. Endpoints: public `GET/POST /api/messages` (GET: `limit` max 50, `offset` or the older `before` cursor, returns `{messages,hasMore,total}`), `POST /api/rsvp`, `GET /api/config`, `GET /api/health`; admin (`Cf-Access-Jwt-Assertion` verified, fails closed with 503/403) under `/api/admin/*`, including permanent `DELETE /api/admin/{messages,rsvps}/{id}` (the admin UI asks to confirm in a modal first). `GET /api/admin/messages` takes `sort=date|name|status`, `dir=asc|desc`, `status=all|hidden|shown`, `offset`, `limit` (default newest first; limit default and max 1000) and returns `{messages,total,counts}`, which the admin Wishes list uses for infinite scroll: `@tanstack/react-virtual` element virtualizer in `AdminApp.tsx`; the admin page itself does not scroll (`h-dvh`), the title, tabs and controls stay put and only the list box scrolls, 30-row pages fetched by index as rows near the viewport need them, refetched in place after hide/show/delete. `GET /api/admin/rsvps` takes `sort=date|name` and `dir`; it sorts after the summary and superseded marks are computed. Name order ignores case and Vietnamese tones (`NAME_FOLD` collation, `store.go`). nginx proxies `/api/` to it. The admin UI is `frontend/src/components/admin/AdminApp.tsx` served at `/admin`.
- `cloudflared` — its own tunnel (token in `.env` as `CLOUDFLARE_TUNNEL_TOKEN`) routing linhhy.namgold.com → `http://frontend:80`
- No host port published; the tunnel reaches nginx over the compose network.
- Design: since 2026-11-16 the owner asked for the frontend to match the original boho-floral-pink template saved in `temp/origin/index.html` (palette `#9D6D63`/`#FFFAF7`, Times/Baskerville body, Playfair/EB Garamond/Ms Madi names, px-offset floral art with scroll parallax via `--s` in `components/Floral.tsx`). Floral art in `public/images/floral` and `public/images/giftbox` is the template vendor's: check licensing before the site is promoted. Do not copy its code or sample text.
- Two different QRs: the **site QR** (invitation, opens a place's URL, 3 variations) and the **bank QR** (`components/Qr.tsx`, gift box, optional with an on/off switch). The bank QR is hidden by `wedding.showBankQr = false` in `data.ts` (the QR image is still a fake placeholder). The 3G performance budget is not set yet.

## Running
```
cd frontend && npm install && npm run dev        # UI only: no /api proxy, forms show a network error; use compose for full stack
cd frontend && npm run build                     # static export to frontend/out
cd frontend && npx tsc --noEmit -p .            # typecheck (there is no ESLint config; `npx eslint` errors out)
docker compose up -d --build                     # REPLACES THE LIVE SITE via the tunnel
dcu --build frontend                             # fish alias dcu = docker compose up --detach; rebuilds only the frontend (use `api` for Go changes). Agents run bash, so use `docker compose up -d --build frontend` (or `api`)
docker compose logs api cloudflared
docker run --rm --network namgold-wedding_default curlimages/curl -sS -o /dev/null -w "%{http_code}\n" http://frontend:80
```
To test an image without touching the live site, build it under another name and run it without the tunnel (`docker build -f frontend/Dockerfile -t wedding-test .`). `docker run -p` ports may not be reachable from the shell here; test with `--network container:<name>`.

## Go API (no Go on the host: use Docker)

**Schema changes:** `CREATE TABLE IF NOT EXISTS` never alters the live `wedding.db`. The API does not know place slugs (shape check only), so renaming a place needs no API change; only the Telegram RSVP text labels the 3 known slugs (`placeNames` in `integrations.go`, unknown slugs show as is).
Env vars are listed in `.env.example`; all optional except the tunnel token.

## Telegram notifications
- Two bots, one per kind, each with its own chat: `TELEGRAM_{WISH,RSVP}_BOT_TOKEN` + `TELEGRAM_{WISH,RSVP}_CHAT_ID` in `.env`; a kind is off unless both of its values are set. Live: `namgold_wedding_wish_bot` posts wishes to the group "Wish bot", `namgold_wedding_RSVP_bot` posts RSVPs to the group "RSVP bot" (each group = owner, wife, bot; bots need no admin rights in a group).
- Texts are Vietnamese plain text, built by `wishText` and `rsvpText` in `api/integrations.go` (tests in `TestTelegramText`): wish = tên, lời chúc; RSVP = tên, bên (Nhà gái / Nhà trai), địa điểm, tham dự (có + số người, or không thể tham dự). The place shows as a name from `placeNames` with no URL or slug (the `/` page is the `wedding` slug); an unknown slug is shown as is.
- **A group's chat id changes when Telegram upgrades it to a supergroup** (`-123456789` becomes `-100...`, e.g. after turning on topics). Sends then fail with `telegram_bad_status` 400. Get the new id from `getUpdates` (the `migrate_to_chat_id` field) or `getChat`, update `.env`, then `docker compose up -d api`.
- The bots have privacy mode on, so in a group `getUpdates` only shows commands, @mentions and replies. To find a group's id, send `/start@<bot username>` there. Sending needs no privacy change.
- Trigger a test without the site (writes a real row into the live data): `docker run --rm --network container:namgold-wedding-api curlimages/curl -sS -H 'Content-Type: application/json' -d '{"name":"T","side":"bride","attending":true,"guests":2,"place":"wedding"}' http://localhost:8080/api/rsvp`; wishes go to `/api/messages` with `{"name":"T","message":"x"}`.

## Verifying UI changes
No-leak check for the "no central page" rule: after a build, run `docker exec <ctr> sh -c 'cd /usr/share/nginx/html && grep -rlF "<another place venue>" .'`. Each place's venue, name and address must appear only in that place's own `<slug>*.html/.txt` files, never in `_next/static` chunks or another place's files.
Build a throwaway image, run it, point the Playwright container at `http://localhost` via `--network container:<name>`. Check: no console errors, no horizontal overflow at 390px, `/` returns the wedding page and `/en` returns 404. For full-stack checks put the api image (`--network-alias api`) and the frontend image on a throwaway network and point Playwright at the frontend container (`/api/admin/*` needs a Cloudflare JWT, so mock it with `page.route`; auth itself is covered by the Go tests).
Playwright container: a bind-mounted script from here shows up as an empty dir, so feed it on stdin: `docker run --rm -i --network <net> mcr.microsoft.com/playwright:v1.56.0-noble sh -c 'mkdir -p /w && cat > /w/t.mjs && cd /w && npm i playwright@1.56.0 --silent >/dev/null 2>&1; node t.mjs' < t.mjs`. `innerText` applies CSS `text-transform` (uppercase), so match text case-insensitively. A reused test API container keeps data between runs, so use `.first()` on text locators.
The whole page is rendered (and server-rendered into the HTML) from the start, under the cover; see "Preload" in Frontend notes. To check what a guest sees, open the page in Playwright and click the cover button ("Mở thiệp" on `/<slug>`, "Open invitation" on `/en/<slug>`) before reading `innerText`, since the page is `inert` and clipped until then.
Screenshot out of the Playwright container: write the PNG to `/tmp/x.png`, log to stderr (`node d.js >&2`), then `cat /tmp/x.png` to stdout and redirect it to a file on the host.
Quick loop: `docker build -q -f frontend/Dockerfile -t wedding-test . && docker run -d --rm --name wedding-test-ctr wedding-test`, run the Playwright container with `--network container:wedding-test-ctr`, then `docker rm -f wedding-test-ctr`. Mock `/api/admin/*` and `/api/messages?*` with `page.route` (add a delay to see skeletons). For skeleton or row heights compare `getBoundingClientRect().height` of the skeleton and the real card.
Memory/DOM-node checks: "nodes keep growing while scrolling" is usually detached nodes awaiting GC, not a leak. Confirm with CDP `HeapProfiler.collectGarbage` then `Performance.getMetrics` (nodes return to about 350). Keying virtual rows by `index % N` does NOT recycle elements; use `lib/useRowSlots.ts`.
After renaming or deleting a route, `tsc` fails on stale `frontend/.next/types`: `rm -rf frontend/.next/types`.
nginx `try_files` on a directory with no index returns 403. Any route directory under `out/` that is not a page needs an explicit `return 404` (done for `/`, `/en`, `/index.html`, the base image's stock welcome page).

## Frontend notes
- Preload: `Invitation.tsx` always renders the page sections; the cover (`fixed`, opaque) sits on top and the page wrapper is `inert` and `h-dvh overflow-hidden` until opened, so images, fonts and the guestbook's first page load behind the cover and nothing scrolls or takes focus. Never hide it with `display:none` (FitText and the guestbook virtualizer need layout; fonts and lazy images would not load). Do not add `loading="lazy"` to Album or GiftBox images (it would defeat the preload). Not preloaded on purpose: the 5 MB mp3 (`preload="none"`) and the Google Maps iframe in `Venue.tsx` (`loading="lazy"`, though Chrome may still fetch it early).
- Music: the `<audio>` lives in `Invitation.tsx` (the cover's Open click calls `play()` so iOS allows it); `components/Music.tsx` is the button; `lib/focusFade.ts` fades out and pauses when the page is hidden, resumes with a fade-in when visible (focus alone does not matter). Test by overriding `document.hidden` and dispatching `visibilitychange` in Playwright.
- Cover opening (`Cover.tsx`, keyframes in `globals.css`): click calls `onOpen` at once (the parent starts the music there, so iOS allows it), then `idle` → `opening` (seal breaks, ring, heart blooms, soft Web Audio chime) → at 500 ms `away` (32 petals burst, card flies up 0.8 s, backdrop fades) → at 1300 ms `onDone`, and the parent unmounts the cover and shows `Music`. Ported from the original `EnvelopeCover` in `temp/origin/_next/static/chunks/57034-*.js`. With `prefers-reduced-motion` it skips the animation and calls `onDone` at once. Burst particles use `Math.random` inside the click handler only (never at render, or SSR and client markup would differ).
- Text that must fit one line (names, the date line) uses `components/FitText.tsx`, which measures its parent: the parent must be a block element (an inline parent measures 0).
- Language: `Invitation.tsx` holds `lang` in state with both `vi` and `en` copy; the VI | EN toggle (`LangToggle.tsx`) swaps text in place and syncs `<html lang>`, title, meta description and the URL via `history.replaceState`. Pages only pass `initialLang`. Test by clicking the toggle in Playwright and checking a `window` marker survives (no reload).
- Guestbook (`Guestbook.tsx`): virtualized with `@tanstack/react-virtual` inside its 640px scroll box; it knows `total` from the API, so the scroll bar is full length from the start, and pages (`offset`/`limit`) load only for the rows in range. Paging, reload and failed-page tracking live in `lib/usePagedRows.ts`, shared with the admin Wishes list; a failure shows an error with a retry. Row elements are recycled through `lib/useRowSlots.ts` (also used by the admin list) so scrolling leaves no pile of detached DOM nodes. The `guestbook.loadMore` copy string is unused now.
- Skeletons (no "Loading…" text anywhere, guestbook and admin): one bar per text line (guestbook card: name, date, two message lines), each bar in a line box of the real line height, so a skeleton card measures the same as the real one (guestbook 107.5px, admin wish 106px, RSVP 86px, stat 74px; re-measure in Playwright after changing a card's padding or text size). Guestbook: `GuestCard` in `Guestbook.tsx`; admin: `WishSkeleton`, `RsvpSkeleton`, `SkeletonList` in `AdminApp.tsx`.
- Add to calendar (the link under the calendar and the whole month calendar box, a `role="button"` div with Enter/Space support, both in `Reception.tsx`; do not nest a button in it; a calendar-plus icon at the right end of the month header tells guests it is tappable; on hover, and while a finger is down on touch (tracked with `touchstart`/`touchend` into `data-pressed`, not `:active`, because the browser drops `:active` when a scroll starts; it stays until the finger lifts), the box lifts 3px diagonally and leaves an offset rose shadow; Tailwind v4 applies `hover:` only on hover-capable devices, so touch has no sticky hover; the box has a 90% blush background, `bg-blush/90`, so the floral art does not show through the text): `prefersIcs()` in `lib/date.ts` picks by user agent. iOS/iPadOS and desktop Safari go to the static `/<slug>/calendar.ics` (`/en/<slug>/calendar.ics`; it carries two reminders, 2 h and 30 min before, `REMINDERS_MIN` in `lib/date.ts`; route handlers using `lib/icsRoute.ts`; nginx serves `.ics` inline as `text/calendar`) so the native Calendar sheet opens; everyone else opens a prefilled Google Calendar link in a new tab. Not testable on real devices from here (Playwright only checks which URL is opened).
- Wish form (`WishForm.tsx`): the card is `!bg-blush/85` (the `!` beats the `.card-surface` background in `globals.css`) so the floral art does not show through the text; the inputs inside (`.field`) are still transparent.
- Parallax floral art: `components/Floral.tsx`, scroll offset in the `--s` CSS variable.
